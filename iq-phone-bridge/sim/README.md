# FR235 crypto simulator tests

This harness executes the handwritten Monkey C SHA-256, HMAC-SHA256, and
AES-256-CBC implementation on Garmin's FR235 Connect IQ simulator, and compares
its outputs byte-for-byte with vectors generated by crabnnb's Rust crypto and
heartbeat implementations. It also checks the complete 81-byte bridge
heartbeat and invalid input handling.

## Prerequisites

- Podman, with the running Connect IQ SDK container (default name `ciq-sdk`).
  The container must have the Garmin SDK installed under
  `~/.Garmin/ConnectIQ/Sdks`, Java, `Xvfb`, and OpenSSL.
- Rust/Cargo on the host, since `cargo xtask iq-vectors` creates the oracle
  vectors.
- The host project directory must be mounted at the same absolute path inside
the container. The existing `ciq-sdk` distrobox satisfies this requirement.

Run from the repository root:

```sh
iq-phone-bridge/sim/run.sh
```

Override the Podman container with `CIQ_CONTAINER=...`. The container selects
the newest installed SDK by default; set `CIQ_SDK_PATH` to an SDK directory
inside the container to choose a specific one. The simulator targets `fr235`.

The harness creates a temporary copy of the app, installs generated vectors
and test-only Monkey C functions there, and removes it when finished. The test
app reports its result over a loopback HTTP endpoint in the SDK container; the
harness waits for that report and treats a timeout as failure. Set
`CIQ_TEST_TIMEOUT` to change the wait (seconds), or `CIQ_TEST_PORT` if the
collector's default port is already in use.

No test code, generated vector, developer key, or test app ID enters the
production Connect IQ project. A generated one-off signing key is used only
for the simulator build.
